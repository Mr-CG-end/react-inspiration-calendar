# react-inspiration-calendar 需求文档

## 项目定位

将现有的"源境日历"React 应用改造为**可发布的 npm 组件库**，供其他开发者安装使用。

## 目标用户

需要在自己的 React 项目中嵌入一个美观的灵感日历卡片的前端开发者。

---

## 功能需求

### F1：自定义内容数据

- 用户可通过 Props 传入**一条或多条**自定义数据，替代日历卡片中的文字内容（活动、引言、作者、出处）
- 支持两种数据来源方式：
  - **静态数据**：直接传入数据对象或数组
  - **API 数据**：传入一个异步函数，组件内部调用获取数据
- 当传入多条数据时，按日期自动匹配（每条数据需携带 `date` 字段）；无匹配时使用默认备用内容
- 当未传入任何数据时，显示默认的备用内容

### F2：日期与农历

- 日期分为两种模式：
  - **默认模式**：自动使用今日日期
  - **指定模式**：用户通过 Props 传入自定义日期
- 显示**真实的农历日期**（月份、日期），替代当前的模拟数据
- 需要引入农历计算库（如 `lunar-javascript`）

### F3：样式切换

- 支持多种日历卡片样式（主题/皮肤）
- **v1 交付 3 种样式**：
  - `classic`：当前已有的 SVG 黑白中式排版样式（默认）
  - `dark`：深色背景 + 金色衬线字体高级感风格
  - `minimalist`：浅色极简排版，大留白风格
- 通过 Props 切换样式（如 `theme="dark"`）
- 架构上需要让新增样式变得简单（可扩展设计）

### F4：显隐控制

- 日历组件**默认显示**
- 提供一个 Props 开关（如 `visible`），控制组件的隐藏/显示
- 隐藏时不渲染 DOM（而非仅 CSS 隐藏）

### F5：移除 AI 服务

- 移除对 `@google/genai` 的依赖
- 移除 `geminiService.ts`
- 移除环境变量相关配置（`.env` 中的 `GEMINI_API_KEY`）
- 内容数据完全由用户提供（见 F1）

### F6：暂不实现多语言

- 当前版本不做国际化
- 架构上不需要预留 i18n，后续有需要再加

---

## 非功能需求

### NF1：npm 包发布

- 构建产物为 **ESModule + CommonJS** 双格式（不含 UMD）
- 包含 TypeScript 类型声明文件（`.d.ts`）
- React 作为 `peerDependencies`，不打包进库

### NF2：低配置可用

- `npm install` 后，最简使用只需导入组件 + 手动引入样式文件即可展示日历
- 所有 Props 都有合理的默认值

### NF3：样式隔离

- 组件样式不污染宿主应用
- 不依赖 Tailwind CSS（宿主应用无需安装 Tailwind）

---

## 不做的事情（当前版本）

- ❌ AI 内容生成
- ❌ 多语言/国际化
- ❌ 日期选择器 UI（组件本身不提供日期选取交互，日期由外部控制）
- ❌ 图片导出功能
